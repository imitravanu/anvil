## Findings (new, verified against live code)

### A1 — LSP integration never sends `textDocument/didOpen` (HIGH, correctness)
`packages/core/src/lsp/client.ts` opens a server per call, sends definition/references/hover, but never
`didOpen`. Per LSP spec, undefined results are valid responses for unopened documents — most servers
(e.g. typescript-language-server) return null for anything not opened first. Net effect: the LSP path
likely returns zero results in production while tests (with mocks) pass. Fix: in `withClient`, send
`didOpen {textDocument:{uri, languageId, version:1, text}}` before `fn(client, abs)`; need the file text
(already read by the fallback path — hoist the read). Also send `didChange` on edit if a persistent
client is introduced.

### A2 — LSP client spawns a server process per tool call (HIGH, resources)
`withClient` starts and closes an `LspStdioClient` per invocation; `get_diagnostics` additionally
spawns a server just to read diagnostics collected since ITS spawn (nearly always empty → silent
fallback). Fix: per-language client cache keyed by `language+projectRoot` with idle timeout + abort
hook; keep a reference from A1's didOpen state.

### A3 — Plugin tool commands: `{input}` replaced with raw JSON via `.replace()` (HIGH, security)
`packages/core/src/plugins/registry.ts:45`: `tool.command.replace("{input}", JSON.stringify(input))`.
`String.replace` treats `$&`, `$'` etc. in the replacement as pattern references — a model-controlled
string containing `$&` corrupts or injects into the rendered shell command. Also `replace()` replaces
only the FIRST occurrence. The command then runs via `bash -c` (permission-prompted, but the template
is user-installed — document the trust boundary). Fix: replacement-function form
`replace("{input}", () => json)` (or `replaceAll`); validate templates at manifest load; consider an
argv-passing contract instead of shell strings.

### A4 — `rm -rf` blocker misses newline-separated commands (MEDIUM, defense-in-depth)
`packages/core/src/tools/bash.ts:100` splits segments on `/[|;&]+/` — newline is also a bash command
separator. A raw multi-line command can defeat segment isolation. Fix is trivial: add `\n` to the
split class (`/[|;&\n]+/`) plus a unit test with multi-line payloads.

### A5 — `/context` uses `FALLBACK_CONTEXT_WINDOW` (32k) instead of the model's real window (MEDIUM, honesty)
`packages/tui/src/commands/handlers/phase25.ts:15` hardcodes the fallback while compaction
(`session.ts:437-441`) resolves `getModel(...).contextWindow ?? FALLBACK_CONTEXT_WINDOW`. For a 200k
model the shown utilization is ~6x overstated. Fix: expose `session.contextWindow` and use it.

### A6 — Phase-25 headline features are dead code / not wired (HIGH, "not finished")
Verified zero non-test callers for: `runTeam` (agent/team), `interceptTurn` (guardian/interceptor),
`registerPluginExecutors` (plugins/registry), `selectiveKeep` (agent/context). `/team` prints "no
running team" (stub). Guardian auto-fix never runs in the turn loop. Plugins load for `/plugin list`
but their tools never reach the model. CHANGELOG 1.0.0 oversells 25.2/25.4/25.6. Fix: wire
(guardian→orchestrator pre-write, plugins→toolDefs, team→delegate_task or `/team run`) or downgrade
the changelog/README claims. Multi-agent protocol fix (AGENTS.md): add "runtime call-path proof
(grep callers + run the feature)" to the definition of done.

### A7 — `get_diagnostics` LSP path almost always empty (MEDIUM)
Consequence of A2's per-call spawn: diagnostics collected since its own spawn ≈ always []. Fix:
persistent clients (with A1's didOpen + time to collect).

### A8 — README drift (LOW)
README says "Agent loop with 11 tools"; the registry now has 15 (11 + 4 LSP tools). `/context`,
`/team`, `/plugin`, `anvil gate`, `anvil init --guarded` are missing from the README's feature list.

### A9 — LSP fallback re-reads the file even when LSP succeeded (LOW, perf)
Minor cleanup when touching A1: derive the symbol once and pass it through.

### A10 — Abort/retry hygiene verified clean (INFO)
`sleepAbortable` wakes on abort; orchestrator attach/detach in `finally` prevents listener leaks;
rate-limit retry path checked — no action needed.

## Validation notes
- The `get_diagnostics` unit test that shells out to real `npx --no-install tsc` was flaky under
  parallel load (5s default timeout on a genuinely slow subprocess); given an explicit 20s timeout.
- **as unknown as { unref }** (timer unref, matching the MCP transport's existing pattern) is not an
  `as any`/`as never` escape, so it satisfies the constitution and the gate.
- **Gate/list sync invariant learned**: when a file is promoted to `PROTECTED_PATHS` in the gate, THREE
  places must change in the same commit — the gate's list, `scripts/gate-manifest.json` (with live hash),
  and the sentinel test's `required` list in `packages/cli/src/__tests__/gate.sentinel.test.ts`
  (which then also changes the sentinel's own hash → manifest again). The sentinel test enforces this
  (exact `toEqual` on manifest keys), so the failure mode is loud, not silent.
- **scripts/ type coverage gap**: `packages/tui/scripts/ui-preview.tsx` had a real type error
  (2-arg `render()`) that no `tsconfig` covers (`include: ["src/**/*"]`) and the gate scans patterns,
  not types. It only surfaced when the gate's new residual-dir discovery forced the file to be opened.
  Consider a `tsconfig.json` for `scripts/` or adding `scripts` to workspace typecheck.

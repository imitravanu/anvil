## 2. A — Measurement integrity (Phase 38.4)

The harness that must gate the 38.5 prompt rewrite was itself found to still violate the phase's own premise.

**A1 [P1, V] — A/B budget: the floor is a cap.**
`packages/core/src/eval/experiment.ts:146-152`
```ts
// maxTokens is a FLOOR, not a cap — a reasoning model that burns
// its budget before answering returns an empty turn, ...
maxTokens: Math.max(arm.profile.maxTokens ?? 0, EVAL_AB_MAX_TOKENS),
```
`packages/core/src/eval/runner.ts:163-172` gives `overrides?.maxTokens ?? profile.maxTokens` — so the value is always defined and always replaces the task budget. `EVAL_AB_MAX_TOKENS = 4_096` (`config/constants.ts:95`) vs `DEFAULT_MAX_TOKENS = 8_192` (`:26`); tasks 21–25 declare `"maxTokens": 8192`. **Every A/B run scores a 4,096-token agent while shipping uses 8,192.** Fix: apply the floor only when an arm explicitly sets a budget, otherwise pass `task.maxTokens` through untouched; pin with a parity test (the class of test 38.1 introduced).

**A2 [P1, V] — Significance attributes wins to the wrong arm.**
`packages/core/src/eval/experiment.ts:254-284, 315-337`
```ts
if (Math.max(...rates) === Math.min(...rates)) continue; // no difference
consistent.push(taskId);
...
reason: `${leader} wins ${consistent.length} task(s) unanimously across ${rounds} trials ...`
```
`consistent` collects tasks where the arms differ — **in either direction** — and is never tied to `leader` (the aggregate winner). Counterexample: 5 tasks where arm A wins 3 consistently and arm B wins 2 consistently; if ≥`EVAL_AB_MIN_SIGNIFICANT_TASKS` (default 2) then `significant: true` fires and the reason claims *the aggregate leader won all 5 unanimously*, which may be false for either arm. Fix: record each consistent task's winner; require it to equal the leader; otherwise report an honest split. The verdict line is intended to be quotable — right now it can be wrong.

**A3 [P2, R] — Pacing option is dead in the A/B lane.** `betweenTaskDelayMs` is spread into `runEvalTask`, but its only consumer is `runAllEvalTasks` (`runner.ts:326`). Live A/B runs get no rate-limit pacing — which then surfaces as provider errors that get *excluded*, shrinking effective trials. Fix: sleep in the arm loop or route through `runAllEvalTasks`.

**A4 [P2, R] — The "harder tier" 38.4 requires was not delivered.** `docs/PHASE-38-ROADMAP.md:314-323` says "Tasks must come from the harder tier … the current 25 short tasks are saturated"; `evals/ab.ts:28` still points at `tasks/` (25 files). Fix: author long-horizon fixtures, or record the missing tier as an explicit open item in the phase doc.

**A5 [P2, R] — Two different task filters under one flag.** `experiment.ts:133-135` filters case-sensitively on `id` only; `runner.ts:318-321` lowercases `id + name`. `--filter Multifile` silently selects zero tasks in A/B. Fix: one shared `matchesTaskFilter`.

**A6 [P2, V] — The seam test cannot fail; the seam is not observed.** `packages/core/src/eval/__tests__/experiment.test.ts:168-188` runs against a nonexistent fixture path, `.catch((err) => ({ error: String(err) }))` then `expect(result).toBeDefined()` — passes on any throw (and uses the banned `String(err)` form). `:118-143` builds `seen` from the arm definitions, not from runs, so even a missing seam is invisible. Fix: assert the concrete error and observe the resolved profile in a run record.

**A7 [P3, R] — Arms are run arm-major, not interleaved.** `experiment.ts:137-140` — provider drift correlates with arm. Fix: interleave or randomize arm order per trial.

**A8 [P3, R] — Env-failure classification is free-text.** `experiment.ts:104-108` matches `403|unauthorized|credit…` against the message; a graded task failure containing the word "unavailable" can be excused. Fix: match on structured status/code where available.

## 3. B — Certification and provider accounting

**B1 [P1, V] — Mock runs default to live provenance.**
`packages/core/src/cert/runner.ts:549-555`
```ts
// ...so a mock pass is never badged as a live probe.
const recorded = setModelCertification(model, provider.id, status, undefined,
  options.mock ? "mock" : "live");
```
`mock` is optional (`cert/types.ts:30`) and `options.mock ? "mock" : "live"` reads **live when omitted** — the opposite of the comment. `cert/__tests__/certify.test.ts:103` calls `certifyAllProviders(mockProviders, { timeoutMs: 5000 })` with no flag, so the suite stamps 12 registry rows `status: live / mode: live` in-process today. This is the exact defect class Phase 38.3 was written to close. Fix: require the flag, or invert the default (`options.mock === false ? "live" : "mock"`).

**B2 [P2, R] — Certification criteria are weaker than the badge.** `cert/runner.ts:406-490`: `testErrorPath` passes on *any* caught throw; `testRateLimit` exercises only local backoff helpers (no provider probe); the streaming criterion never checks `ANVIL_STREAMING_CERTIFIED`. **B3 [P2, R] — Buffered usage is discarded on mid-stream error.** `providers/openai.ts:110-115` and `providers/gemini.ts:124-131`: the catch yields an error and `return`s before the trailing `if (usage) yield { type: "usage" ... }`. **B4 [P2, R] — `null`/`""` pricing passes the free gate.** `providers/freeModels.ts:84-95`: `Number(m.pricing?.prompt)` → `null`/`""` coerce to `0`, and `hasPricing` only checks that pricing is an object, so bogus rows are ingested as $0 free models. **B5 [P3, R] — Gemini explicit zero folded to undefined.** `providers/gemini.ts:111-119` says "no reasoning field" and "zero reasoning tokens" stay distinct, then folds `?? 0` to undefined; `usageAccounting.test.ts:90-104` is titled for the distinction and asserts `toBeUndefined()`. Fix: branch on `typeof === "number"`, or fix the comment and title.

**B6 [P3, R] — First-event reclassification ignores structured fields.** `providers/base.ts:50-60` reclassifies retryability from `first.value.message` only, ignoring the event's own `code`/`isRetryable`. Fix: prefer the structured fields.

**B7 [P3, R] — Unbounded error path.** `providers/gemini.ts:55-72`: the 600-char cap applies only to the fallback branch, not the nested-message branch.

**B8 [P3, R] — Free-model merge never refreshes metadata.** `providers/freeModels.ts:499-529`: matched rows keep stale `contextWindow`/`capabilities`/`displayName`. Also synced rows omit `certified`, and `tui/util/format.ts:83-84` renders `undefined` as no badge instead of `[⚠ untested]`. Fix: refresh on match; default the badge honestly.

**B9 [P3, R] — Magic constants in providers/cert.** `base.ts:56,79` (`50 * 2^attempt`, capped `2000` — `RATE_LIMIT_*` already exist at `constants.ts:160-162`); `freeModels.ts:66,177` (4000/8000); `cert/runner.ts` (150/100/50, `?? 30_000`). Fix: import/hoist.

## 4. C — Agent loop, sessions, goal, team

**C1 [P2, V] — Token calibration converges to √ratio, not ratio.**
`agent/session.ts:676-690` multiplies the estimate by the current factor and passes the **scaled** number to `nextCalibration`:
```ts
const estimatedInput = estimateTokens(messages) * this.calibration;
...
this.calibration = nextCalibration(this.calibration, usage.inputTokens, estimatedInput);
```
`context/scoring.ts:53-58` computes `ratio = measured / estimated`. The recurrence's fixed point is `c* = measured / (raw · c*)` → **`c* = √(measured/raw)`**. A provider that counts 2× the estimator drives the factor to 1.41, not 2.0 — compaction fires late by ~29% in that case. Fix: pass the unscaled estimate; add a moderate-ratio multi-turn convergence test.

**C2 [P1, V] — A hedge is read as satisfaction.**
`agent/goal/goalEngine.ts:135-139`
```ts
const startsYes = /^YES\b/i.test(trimmed);
const isHedge = /^YES\s*[,]\s*(but|however|although|except|unfortunately)/i.test(trimmed);
return startsYes && !isHedge;
```
The engine's own prompt (`:284`) asks for `YES or NO followed by " — " and a one-line reason`. `"YES — however the criteria were not met"` satisfies this predicate: the milestone is marked complete and becomes auto-committable. Fix: accept any separator before the hedge word (and test the prompted form against the imported function — `phase22.test.ts:77-81` re-implements the predicate inline).

**C3 [P2, V] — Ctrl+C during the final critique can still exit 0; goal cancellation never reports 130.**
`cli/goalRunner.ts:31-39` cancels the engine on the first Ctrl+C; `goalEngine.ts:352-391` uses `critique.cancelled` only to pick fallback text, then still yields `goal_completed` with `success = allCompleted`. `EXIT_CANCELLED = 130` (`terminalRenderer.ts:21`) has no goal-mode path, so a cancelled mission exits 1 and a cancelled-in-critique mission can exit 0. Fix: return a cancelled result after the critique turns; map to 130.

**C4 [P2, V] — A crashed sub-run is reported as "aborted", and the ledger says ok.**
`agent/subagent.ts:137-141` on any thrown error sets `aborted = true` **and** `failureReason`; `tools/delegateTask.ts:340-356` checks `aborted` first and returns `{ error: "aborted" }` — the real reason never reaches the user. On the non-aborted path the ledger still records `outcome: "ok"` (`:364-371`) even when `run.failureReason` is set (`:379-387`). The team adapter gets this right (`:208-214`). Fix: separate crash from cancel, surface the reason, mirror the team adapter's outcome logic.

**C5 [P2, V] — Guardian auto-fix drops fixes for non-`content` bodies while allowing the call.**
`agent/guardianIntercept.ts:16` scans six body keys (`content, new_str, new_content, text, body, data`); the write-back at `:118-127` only handles `content`/`new_str`; `interceptor.ts:110` then reports `allowed: violations.length === 0` with the fix counted. Any external tool whose body came from the other keys executes the original slop *and* the violation was cleared. Fix: write back the key that produced the body, or block non-writable keys instead of reporting them fixed.

**C6 [P2, R] — Auto-fix rewrites to `getErrorMessage` without ensuring the import.** `guardian/interceptor.ts:114-117`; `scope.ts:12-14` documents the hazard only for foreign projects; tests cover foreign scope only. On an Anvil file without the import the "fix" is a compile error. Fix: verify/insert the import, or skip auto-fix when unresolved.

**C7 [P2, V] — `autoCommitMilestone` sweeps the whole index.**
`git/gitUtils.ts:44-52`: stages scoped paths with `git add -- ...scoped`, then commits with a **bare** `git commit -m` — any user pre-staged tracked change is swept into the milestone commit. The doc comment above it ("must never be swept into history") describes a guarantee the code does not provide; the test only writes untracked files and never pre-stages. Fix: `git commit -m msg -- ...scoped` (or `--only`), plus a pre-staged-file test.

**C8 [P2, V] — Memory cap rewrite deletes headerless content.**
`config/memory.ts:113-126`: `splitMemorySections` keeps only header-delimited sections (`if (current !== null ...) sections.push`), and on overflow the rewrite keeps `kept.length > 0 ? ... : newSection` — a preamble or a hand-edited headerless file is silently destroyed. The comment claims such content "is one section". Reached via `updateMemory`. Fix: treat preamble/headerless content as a section; add a cap-overflow test for it.

**C9 [P2, R] — Team strategy is a string cast, and unknown values fall through.** `tools/delegateTask.ts:85,109` only checks `typeof === "string"` then casts; `agent/team/runner.ts:20-39,60` validates members but never strategy membership, and an unknown strategy takes the pipeline branch — bypassing the pipeline's min-2-member rule. Fix: runtime-validate the enum.

**C10 [P3, R] — Team budget comment overstates.** `delegateTask.ts:115-117,173`: clamps are per-member and the aggregate can exceed `totalIterations` (test blesses 2+2 with budget 3 at `teamBudget.test.ts:261-288`); `Math.max(1, …)` also forces ≥1 per member. Reword or enforce.

**C11 [P3, R] — `TeamMemberSpec.maxInnerIterations` is documented but never read by `runTeam`** (`team/types.ts:15-16`); only delegateTask's own override map honors it, and its member mapping drops the field. Honor or remove.

**C12 [P3, V] — Dead guard in `delegateTask`:** `settledError`/`settledResult` plumbing (`:235,239,248,262-263`) is unreachable — the rejection handler rethrows, so `await runPromise` always throws first. Delete.

**C13 [P3, R] — Ledger usage attribution.** `session.ts:323,692`: the last measured usage is stamped on every `tool_finished` in a batch, and the TUI sums per entry (`tui/util/ledger.ts:18-21`) — totals are overstated. **C16 [P3, R] — Auto-commit catch misattributed:** `goalEngine.ts:317-321,326` swallows `summarizeChanges()` failure and then reports "no session-touched files". Fix: report the real cause.

**C17 [P3, R] — Magic constants:** `awareness.ts:21,28,35` (2000×3); `goalEngine.ts:283,305,311` (2000/300/300); `compaction.ts:211,309` (`4` — `ASCII_CHARS_PER_TOKEN` exists — and 1024); `plugins/registry.ts:92-118` (60_000, 512 KiB, 2000, 8000); `gitUtils.ts:104,112` (2 MiB ×2). Fix: hoist.

## 5. D — AST parser / symbol index (live probe receipts)

Probes ran in this session against the built `packages/core/dist/ast/parser.js`; outputs quoted.

**D1 [P1, V] — Six parser defects, all reproduced.**
- **D1a — Expression-bodied arrow swallows the next declaration.** `ast/parser.ts:591-614` (`findMatchingBrace(i)` with no own-line guard; `i = endLine`). Probe: `const f = (x: number) => x + 1;` + `function g() {...}` → `f@1-2 body:3-2`, **`g` absent**. Live repo instance: `agent/__tests__/phase8.test.ts:69-71` (arrow followed by `describe(...) => {`) swallows the whole block from the index. Fix: brace-match only when `{` is on the arrow's own masked line; else emit a one-liner.
- **D1b — Semicolon-less multi-line type alias swallows the next declaration.** `:412-431` scans forward for *any* line containing `;`. Probe: `type Foo = { a: string }` (no `;`) + `const x = 1;` → `Foo@1-4`, **`x` absent**. Fix: brace-match `{...}`; never scan for `;` across lines.
- **D1c — `pub(crate)` functions dropped.** `:976-977`: `isPub = trimmed.startsWith("pub ")` is false for `pub(crate)`, so `decl` keeps the prefix and the `fn` rule (`:1154`) never matches — even though the very next line's `replace` handles that form. Probe: only `bar` indexed. Fix: strip `pub(...)` first, derive `isPub` from the match.
- **D1d — `impl<T> Foo<T>` yields the garbage name `<T> Foo<T>`.** `:1091-1098`: `replace(/<.*$/,"")` empties the string and `?? target` doesn't rescue `""`. Probe confirmed. Fix: strip leading impl generics and a trailing type-generics group.
- **D1e — Go generic receivers drop the method and leak body vars top-level.** `:1299-1302` requires `\s*\)` after the receiver type (fails on `*Stack[T]`); the unmatched `func` body's `var`/`const` then matches the package-level rule (`:1352-1354`, no brace-depth guard). Probe: `func (s *Stack[T]) Push(v T) { var x = 1 }` → **`Push` absent, `x@2-2` indexed as package-level**. Fix: allow `(?:\[[^\]]*\])?` in the receiver; skip unmatched `func` bodies.
- **D1f — Rust skeleton folds the signature away.** `:881` uses `bodyStart = i + 1` where TS/Go use `i + 2` (`:364`, `:1215`); `ast/folder.ts:46-53,75-77` emits from `bodyStartLine`, deleting `pub fn foo() {`. Probe: `body:1-5` for a 5-line Rust function. Fix: `i + 2`; add a skeleton fixture.

**D2 [P2, R] — Six silent failsafe catches in `ast/symbolIndex.ts`** (`:147,158,235,244,258,271-272`) carry no `// intentional:` comment or log; the gate's `catch {}` regex cannot see them.

## 6. E — Tools, safety, LSP, MCP

**E1 [P2, V] — Safe-list containment is lexical, not real.** `tools/bash.ts:236-251`: `pathsInsideRoot` resolves lexically only (no `realpath`), so a project symlink `link -> /etc` lets `cat link/passwd` auto-approve without a prompt; and `if (rawArg.startsWith("-")) continue; // flags and their attached values` skips fused values wholesale — `wc --files0-from=/etc/passwd` (or `du --files0-from`) is auto-approved and reads host files. Contrast `paths.ts:55-59` which does realpath. Fix: realpath existing prefixes; validate `--name=value` operands (not just their presence).

**E2 [P2, V] — Root-wipe patterns are bypassable in shapes the comment claims to cover.** `bash.ts:146-151` replaces quotes with **spaces**, so `r''m -rf ~` never matches `\brm\b`; `bash.ts:179` `\/(?:\s|$|\*)` misses `rm -rf /?` and brace expansion `rm -rf /{etc,usr}`; the comment at `:177` says "root glob (/*)" as if covered. The file banner calls matching best-effort and the prompt remains the gate — but in `-y`/goal mode this is the only gate. Fix: strip (not space-replace) quotes; match `*?[{` after root separators; correct the comment.

**E3 [P2, V] — LSP stale fallback.** `lsp/client.ts:293-321`: the polling loop filters `val.timestamp >= sinceTimestamp`, but the post-deadline fallback returns the cached entry for the path **without the timestamp check**, so `write_file`/`edit_file` can report already-fixed errors after a timeout. `sensor.test.ts:73-89` mocks `diagnosticsForPath`, so the branch is untested. Fix: re-apply the guard in the fallback; return `[]` when stale.

**E4 [P2, V] — `get_diagnostics` on a directory always probes with `package.json`/tsc.** `lsp/tools.ts:197` substitutes `package.json` for any non-file target; `:198` picks the TS server; `:219` `target.endsWith("package.json")` is then always true — so a Rust/Python project directory runs the tsc branch, no file is `didOpen`ed, and `waitForDiagnostics` returns on *any* diagnostic, not a scoped one. Fix: signal project language from real files; scope the wait; gate tsc on actual TS presence.

**E5 [P2, V] — `getLspClient` race leaks a server.** `client.ts:392-405`: no in-flight promise cache — two concurrent callers both `await LspStdioClient.start`, the second overwrites the map slot, and the loser is never idle-closed (idle close only fires for the mapped instance). Fix: cache the start promise per key; close any client that loses the slot.

**E6 [P3, R] — MCP single 500 fails every in-flight call.** `mcp/transport.ts:708-712`: any POST error (including one HTTP 500) calls `pump.finish()`, failing all in-flight calls and forcing reconnect while the stream is alive. Fix: finish only on transport-level failure; deliver a JSON-RPC error for HTTP status failures.

**E7 [P3, R] — Magic constants in tools/LSP:** `grep.ts:6,153,227` (1 MiB, 200, 300); `outline.ts:241-242` (40, 250); `readFile.ts:65` (8192); `lsp/tools.ts:209,226` (1500, 30_000); `lsp/sensor.ts:14` + `writeFile.ts:75` + `editFile.ts:144` (400); `verifyTests.ts:12-13` duplicate bounds.

**E8 [P3, R] — Dead code / casts:** `verifyTests.ts:5` unused import; `lsp/client.ts:29,210` write-only `opened`; `lsp/client.ts:284-286` `diagnostics()` no production caller; `(err as Error).message` at `editFile.ts:123,125,190` and `grep.ts:179`; `bash.ts:317` command has no `typeof` guard (siblings do).

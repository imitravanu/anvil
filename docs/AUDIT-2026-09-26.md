## 3. What the codebase does well

Specific, because "well engineered" without evidence is worthless.

1. **Failure-mode engineering is real, not aspirational.** Abort propagates through every layer
   (`errors.ts:sleepAbortable`); `bash.ts` kills process *groups* so grandchildren die;
   `readFile.ts` uses open→fstat→bounded read so a size check cannot be raced; `atomicWrite.ts`
   chmods before rename so no world-readable credential window exists.
2. **The MCP SSE transport (`mcp/transport.ts:380-731`) is the reference implementation in this
   repo.** `redirect: "error"` on both GET (`:493`) and POST (`:690`); an off-origin `endpoint`
   event is *terminal, not retried* (`:638-644`); one deadline covers endpoint discovery
   (`:459-482`); one pump per attempt (`:620`); bounded body reads that abandon early rather than
   buffering first (`:414-441`); every error routed through `sanitizeSseUrl`. No defects found.
3. **Truthfulness is a design value.** "Unverified" is a distinct exit code
   (`terminalRenderer.ts:EXIT_UNVERIFIED`); unknown pricing renders `n/a`, never `$0`
   (`eval/cost.ts`); coverage loss is surfaced rather than hidden (`DiffModal` coverage warning);
   a mock certification can never badge as a live probe (`formatCertificationBadge`).
4. **Self-imposed governance that actually binds.** The anti-slop gate, the protected-artifact
   manifest, the sentinel test that runs *outside* the gate, and a pre-commit hook that
   deliberately refuses to execute the worktree's own gate script (an agent could otherwise weaken
   it and flip its exit code). This is rare and well-reasoned.
5. **Tests that prove properties, not happy paths.** The plugin argv test creates a marker file and
   asserts it is *never* created; the 200-sequence property suite asserts history invariants after
   every mutation; `cancelHistory.test.ts` drives a cancellation mid-permission-prompt.

### AUDIT-01 (P1) — an ungated project write · VERIFIED

**Where:** `packages/core/src/tools/updateMemory.ts:19` declares `mutating: false`.
**What it really does:** the executor calls `appendToMemory`, which performs `mkdirSync`
(`config/memory.ts:76`), `writeFileSync` for the auto-created `.gitignore` (`:83`),
`appendFileSync` (`:105`), and a **full-file rewrite** when the 32 KB cap is exceeded (`:125`).

**Why it matters:** `ToolOrchestrator` keys **both** the permission prompt and the
serial-vs-concurrent batch decision off `def.mutating`. The guardian intercepts only calls carrying
a `path`; this tool's input is `entry`. So this is the single tool that writes project files with
no prompt and no guardian pass, while `write_file` — writing the same kind of content — is gated.

**Impact:** bounded. It writes only `.anvil/memory.md` inside the project root, is size-capped, and
carries model-authored prose. It is not an arbitrary-write primitive. But it is an inconsistency in
the trust model, and trust-model inconsistencies are exactly what `write_file`'s prompt prevents.

**Fix options (owner chooses):**
- **(a) `mutating: true`** — one line, fully honest, but every memory note then prompts. Noisy.
- **(b) keep non-mutating, document the decision** — acceptable *only* if written as a deliberate
  exception with its scope (project root, one fixed filename, size-capped), the way this codebase
  documents other deliberate boundaries.
- **(c) split the tool** — `update_memory` becomes gated; an internal non-tool path handles
  guardian/system memory. Most correct, largest change.

Recommendation: (a) now, (c) later. (a) is reversible; (b) is how trust drift starts.

### AUDIT-02 (P2) — provider-blind model metadata in the TUI · VERIFIED

**Measured:** exactly one model id exists under two providers, and its metadata diverges:

```
gpt-4o-mini   openai: window 128000, vision true, isFree FALSE
              github: window 128000, vision true, isFree TRUE
```

**Five call sites** resolve by bare id (VERIFIED, 5 hits at HEAD): `tui/src/util/format.ts:6` and
`:17` (pricing tag, provider name), `tui/src/commands/handlers/media.ts:51` (vision capability),
`tui/src/components/StatusBar.tsx:35` (context window + pricing), `tui/src/components/Header.tsx:24`.

**Why it matters:** `registry.ts` maintains a provider-qualified index *specifically* to prevent
this ("a session asking about its own provider's model must get THAT provider's row") and exports
`getModel(id, providerId)` for it. The TUI does not use it.

**Symptom (INFERRED from the measured divergence):** a user on **GitHub Models** selecting
`gpt-4o-mini` sees the header read `OpenAI · GPT-4o mini` and may see `[PAID]` for a free model —
while the `/model` picker, which reads the per-row `isFree`, shows FREE. One screen contradicts
another about the same model.

**Fix:** thread `providerId` into these helpers and call `getModel(id, providerId)`, keeping a
documented fallback for free-form ids (OpenRouter-style models are intentionally not enumerated).

### AUDIT-03 (P2) — certification verdict silently discarded · VERIFIED

`cert/runner.ts:35` names `github: "Phi-3.5-mini-instruct"`, which is **not in `MODEL_REGISTRY`**.
Measured across all 12 providers: 11 resolve and `setModelCertification` returns `true`; github
returns `false` — and the return value (`:540`) is never checked. The five criteria still run, so
the report shows a full 5/5 pass that changes nothing.

**Fix:** check the return value and fail loudly when the model is unknown; align the cert model with
a registry row (or add the row). Apply the same check to any future `setModelCertification` caller.

### AUDIT-05 (P2) — allowlist contract mismatch across repo shapes · VERIFIED

The *same* regex appears twice: `core/src/guardian/allowlist.ts:28` and `scripts/verify-gate.mjs:300`,
both `/^packages\/[^/]+\/src\//`. Meanwhile `guardian/init.ts:44` provisions `.fresh-allowlist.json`
into **whatever repo** runs `anvil init --guarded` — and a non-Anvil repo has no `packages/*/src/`
layout.

**Consequence:** in a foreign repo, adding a legitimate allowlist entry (e.g. `src/legacy.ts`) makes
the gate **fail** ("Rejected allowlist entry"), while core's reader silently counts it `rejected`.
The escape hatch is a liability outside the monorepo, and the two implementations disagree on the
consequence.

**Fix:** one validator exported by core and imported by the gate; relax the shape rule to "a
repo-relative source file path" (still rejecting directories, globs, non-source paths); add a test
per repo shape. Touching `verify-gate.mjs` is protected-artifact work — owner decision.

## 6. The trust failure this review must record

Earlier in the same working session, **I introduced a shipping-blocker and called it done.** It is
recorded here because the next agent should know the failure mode, not just the finding list.

**What happened.** I externalized three provider SDKs from the CLI bundle for a measured 37%
startup win. The built `dist/index.js` then opens with real top-level imports of
`@anthropic-ai/sdk`, `openai`, and `@google/genai` — packages that must exist in a *consumer's*
`node_modules`. `packages/cli/package.json` had **no `dependencies` field** (verified against
`HEAD` before the fix: `git show HEAD:packages/cli/package.json` → `dependencies: null`).

**Why every check stayed green anyway.** The monorepo hoists `node_modules`, so the build resolves
the SDKs, the gate passes, and all tests pass — while `npm pack` ships a tarball whose entry point
dies on first import for anyone who is not this repository. **I measured the part that stayed green
and reported the whole as shipped.**

**The systemic lesson, and the durable fix.** *A green gate is evidence about code, not evidence
that something ships.* Two findings here (AUDIT-04, and the packaging class generally) live entirely
outside every check this repository has. The fix is a **packaging smoke test**: `npm pack` each
workspace, install `@anvil/cli` into a temp directory with no monorepo present, and run
`anvil --version`. A `bundleDeps.test.ts` guard (external ⇒ declared dependency) now exists and is
correct, but it is still not an install proof. **Treat any future change to build flags, packaging,
or dependencies as unverified until that install path has actually been run.**

**Resolution (verified at `ac7a4c8`).** The instance is fixed: commit `ac7a4c8`
*"revert(cli): ship one self-contained bundle instead of externalizing SDKs"* removed the
`--external:` flags, and `packages/cli/package.json` is back to `dependencies: null` with a
6.5 MB self-contained bundle. A rebuilt `dist/index.js` has **no bare package imports** beyond
`node:`-prefixed (and legacy `fs`/`path`) builtins, and `node packages/cli/dist/index.js
--version` runs. That is the correct call: **the instance traded the 37% startup win back for
correctness, and it should stay that way until plan task A exists.** The startup measurement
(`npm run measure:startup`) should now read ~6.5 MB / ~883 ms again — the win is banked, not
lost, and becomes recoverable the moment an install test makes externalizing safe.
